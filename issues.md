# Static Code Analysis Issues Report: Hotel Booking System

This document catalogs genuine code quality, security, style, and reliability issues identified in `hotel_booking_system.py` using **Pylint**, **Bandit**, **Flake8**, and manual code review.

## Summary Table of Identified Issues

| Issue | Type | Line(s) | Description | Fix Approach |
|---|---|---|---|---|
| Arbitrary Code Execution via `eval()` (Bandit B307, Pylint W0123) | Security (Medium/High) | 42 | `compute_seasonal_rate()` uses `eval(rate_expr)` to dynamically calculate room pricing. An attacker supplying a malicious expression can execute arbitrary Python commands (e.g., `__import__('os').system(...)`), compromising system integrity. | Eliminate `eval()` completely. Use Python's `ast` module to safely parse and evaluate only trusted binary arithmetic expressions involving `base_price` and numbers, and support direct numeric multiplier rates. |
| Shell Command Injection via `os.system()` (Bandit B605) | Security (High) | 58 | `export_room_ledger()` executes a shell command via `os.system("echo ... " + filename)`. Passing an unsanitized `filename` containing shell metacharacters (e.g., `;` or `&`) enables arbitrary shell command injection. Spawning an external shell for console output is also inefficient. | Remove `os.system()` and shell invocation entirely. Use Python's built-in `print()` function formatted with an f-string to log the export message safely. |
| Weak Cryptographic Hash Algorithm MD5 (Bandit B324) | Security (High) | 47 | `generate_guest_hash()` computes guest identifier hashes using MD5 (`hashlib.md5`). MD5 is cryptographically broken and vulnerable to collision and preimage attacks, making it unsuitable for protecting guest privacy or generating secure IDs. | Replace MD5 with SHA-256 (`hashlib.sha256`) with explicit UTF-8 string encoding to provide strong collision resistance and adhere to modern cryptographic standards. |
| Hard-coded Secret Token in Source & Output (Bandit B105, Manual Finding) | Security (Low / Credential Exposure) | 62, 70 | `main()` defines `hotel_secret_key = "HOTEL_ADMIN_RESERVATION_TOKEN_2026"` directly in source code and prints it to standard output. Hardcoding secrets exposes them in version control, and printing leaks tokens in logs. | Remove the hard-coded credential string. Retrieve the token securely from an environment variable (`os.environ.get("HOTEL_SECRET_KEY")`) and only report configuration status without logging raw token values. |
| Dangerous Mutable Default Argument (Pylint W0102) | Bug / Logic Error | 15 | `bookRoom()` uses a mutable empty list `booking_log=[]` as a default parameter. In Python, default arguments are created once when the function is defined; subsequent calls without an explicit argument share and mutate the same list object across different guests. | Change the default parameter to `None` (`booking_log=None`) and initialize a new list inside the function body (`if booking_log is None: booking_log = []`). |
| Broad Exception Handling and Silent Failure (Pylint W0702, Bandit B110, Flake8 E722) | Bug / Error Handling | 26–27 | `cancel_booking()` uses a bare `except:` clause followed by `pass`. This suppresses all exceptions, including `KeyboardInterrupt`, `SystemExit`, and unanticipated runtime errors, silently hiding bugs and hindering troubleshooting. | Replace bare except with an explicit membership check (`if room_num not in room_inventory: return False`) or catch `KeyError` specifically, returning a boolean status indicating success or failure. |
| Unsafe File Handling & Missing Encoding (Pylint R1732, W1514) | Resource Management / Code Quality | 55–57 | `export_room_ledger()` opens a file using `open()` without a `with` context manager and without specifying an encoding. If an error occurs before `close()`, the file descriptor is leaked. Omitting encoding causes platform-dependent behavior. | Use a `with open(filename, "w", encoding="utf-8") as ledger_file:` context manager to guarantee deterministic closure and consistent UTF-8 encoding. |
| Predictable Pseudo-Random Generation (Bandit B311) | Security (Low) | 51 | `generate_booking_ref()` generates booking references using `random.randint()`, which relies on the standard Mersenne Twister PRNG. The sequence is deterministic and cryptographically insecure for reservation tokens. | Use Python's standard `secrets` module (`secrets.SystemRandom().randint(1000, 9999)`), which provides cryptographically strong random numbers suitable for reservation tokens. |
| Unused Local Variable `cleaning_deposit` (Pylint W0612, Flake8 F841) | Dead Code / Code Quality | 31 | `cleaning_deposit = 25.0` is assigned in `check_room_status()` but never used anywhere in the function or module, leaving dead code in the implementation. | Remove the unused variable assignment completely. |
| Unused Import `math` (Pylint W0611, Flake8 F401) | Code Quality / Style | 6 | The `math` module is imported at the top of the file but is never referenced anywhere in `hotel_booking_system.py`. | Remove `import math` to avoid unnecessary namespace pollution and overhead. |
| Non-PEP-8 Naming and Formatting (Pylint C0103, C0209; Flake8 E501, W292) | Style / PEP 8 Compliance | 15, 19, 73 | `bookRoom` violates PEP 8 snake_case conventions; string interpolation uses legacy `%` formatting exceeding the 79-character line limit; and the file lacks a trailing newline. | Rename `bookRoom` to `book_room` (with compatibility alias), use modern f-strings, wrap long lines to 79 characters or fewer, and ensure a trailing newline at EOF. |
| Missing Room Validation in Seasonal Calculation & Cancellation (Manual Finding) | Bug / Reliability | 25, 41 | Passing an invalid or non-existent `room_num` to `compute_seasonal_rate()` results in an unhandled `KeyError` crash, while `cancel_booking()` silently failed without feedback. | Validate room existence in `room_inventory` before accessing dictionary keys, raising an informative `KeyError` or returning a boolean status. |
